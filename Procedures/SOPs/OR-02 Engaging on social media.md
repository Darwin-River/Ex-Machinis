# OR-02: Engaging on social media

1. # <a id="1"></a>Purpose

   1. <a id="1.1"></a>This standard operating procedure (SOP) sets out how the project uses social media to tell people about Ex Machinis, bring in new players, students and teachers, answer their questions, and point supporters to Patreon. Claude drafts; people post.

2. # <a id="2"></a>Roles and responsibilities

   1. <a id="2.1"></a>The project lead owns the project's social media accounts, approves every post, and publishes it. Only people post to the accounts; Claude has no access to them.

   2. <a id="2.2"></a>Claude drafts posts and replies when directed, using the "Machine instructions for drafting social media posts" ([OR-02-M1](../Attachments/OR-02-M1%20Machine%20instructions%20for%20drafting%20social%20media%20posts.md)), and records them in an issue so the project lead can review, edit and publish them.

   3. <a id="2.3"></a>Developers suggest things worth posting by commenting on, or opening, an outreach issue.

3. # <a id="3"></a>Required resources

   1. <a id="3.1"></a>The accounts listed in "Social media accounts and conduct" ([OR-02-A1](../Attachments/OR-02-A1%20Social%20media%20accounts%20and%20conduct.md)).

   2. <a id="3.2"></a>The "Social media post template" ([OR-02-T1](../Attachments/OR-02-T1%20Social%20media%20post%20template.md)).

4. # <a id="4"></a>General guidelines

   1. <a id="4.1"></a>This SOP will be formatted and maintained IAW [QA-01](QA-01%20Writing%20and%20maintaining%20Ex%20Machinis%20standard%20operating%20procedures.md).

   2. <a id="4.2"></a>Follow the voice and conduct rules in [OR-02-A1](../Attachments/OR-02-A1%20Social%20media%20accounts%20and%20conduct.md). In short: be friendly, be accurate, teach something, and keep students safe.

   3. <a id="4.3"></a>Show, don't announce. The best posts show a drone doing something: a short Lua snippet, a screenshot of a drone's page, a leaderboard moment, a failure and the fix.

   4. <a id="4.4"></a>Every post links somewhere useful: the game, a blog post, the player's manual or Patreon. No more than one post in four asks for money.

   5. <a id="4.5"></a>Post regularly rather than in bursts. A steady rhythm of about two posts a week is the target; the project lead can change it.

5. # <a id="5"></a>Procedures

   1. <a id="5.1"></a>Things worth posting come from merged changes ([DV-01](DV-01%20Making%20and%20testing%20game%20changes.md) §5.5), playtest rounds ([DV-02](DV-02%20Running%20playtest%20rounds.md)), new blog posts ([OR-01](OR-01%20Writing%20and%20publishing%20blog%20posts.md) §5.4), teaching materials ([OR-03](OR-03%20Promoting%20Ex%20Machinis%20to%20schools%20and%20learners.md)) and patron updates ([FR-01](FR-01%20Raising%20funds%20through%20Patreon.md)).

   2. <a id="5.2"></a>When directed, Claude drafts a batch of posts per [OR-02-M1](../Attachments/OR-02-M1%20Machine%20instructions%20for%20drafting%20social%20media%20posts.md) and posts them in one issue titled "Social posts: {topic or week}", labeled `outreach`.

   3. <a id="5.3"></a>The project lead edits the drafts as needed, publishes them, and comments on the issue with a link to each published post. The issue is then closed.

   4. <a id="5.4"></a>Questions and comments from the public are answered by the project lead. Claude can draft replies when the project lead pastes the question into an issue or session. A question that reveals a bug, a doc gap or a good idea becomes an issue, per [AD-01](AD-01%20Creating%20and%20resolving%20GitHub%20issues.md).

   5. <a id="5.5"></a>Once a month, alongside the patron update, the project lead notes in the month's outreach issue which posts drew the most attention, so the next drafts can learn from them.

   6. <a id="5.6"></a>Adding or retiring an account is a change to [OR-02-A1](../Attachments/OR-02-A1%20Social%20media%20accounts%20and%20conduct.md), made through an issue and a pull request, and the website's links to social accounts (`resources/views/layouts/app.blade.php`) are updated to match.
