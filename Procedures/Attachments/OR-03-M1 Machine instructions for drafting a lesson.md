# OR-03-M1: Machine instructions for drafting a lesson

1. <a id="1"></a>Always review and follow the most recent version of these instructions.

2. <a id="2"></a>Scope

   1. <a id="2.1"></a>Apply these instructions when directed to draft or update a lesson or unit in `documents/teaching/`.

3. <a id="3"></a>Drafting the lesson

   1. <a id="3.1"></a>Read the lesson's issue, "Audiences and messages" ([OR-03-A1](OR-03-A1%20Audiences%20and%20messages.md)), the existing lessons, and the parts of the player's manual and Lua function list the lesson uses.

   2. <a id="3.2"></a>Copy the "Lesson template" ([OR-03-T1](OR-03-T1%20Lesson%20template.md)) to `documents/teaching/`, named with the lesson's number and a short slug, for example `01-first-drone.md`.

   3. <a id="3.3"></a>Write to the guidelines in [OR-03](../SOPs/OR-03%20Promoting%20Ex%20Machinis%20to%20schools%20and%20learners.md) §4: one class period, a browser only, no student data, and one named programming idea.

   4. <a id="3.4"></a>If the lesson names curriculum standards, such as the CSTA K–12 Computer Science Standards or AP Computer Science Principles, quote each standard's code and wording from the published standard. If you cannot confirm a code, describe the skill without a code and say so in the pull request.

   5. <a id="3.5"></a>Run every step and every code sample on a local world as a student would. Fix the lesson, or post an issue for the game, wherever a student would get stuck.

   6. <a id="3.6"></a>Open a pull request per [AD-02](../SOPs/AD-02%20Working%20with%20branches%20and%20pull%20requests.md) that names the lesson's issue, and say which steps were tested.

4. <a id="4"></a>Provide a concise summary of activities performed and issues encountered when performing these instructions, including the steps tested and any issues posted.
