# DV-01-A1: Docs to keep current

1. <a id="1"></a>When a change affects players, check each of these and update the ones it touches in the same pull request:

   1. <a id="1.1"></a>`documents/players-manual.md`, and its page `resources/views/pages/players-manual.blade.php`: how to play.

   2. <a id="1.2"></a>`documents/design-manual.md`: how the game works inside, and why.

   3. <a id="1.3"></a>`documents/api.md`: the API that players' tools and AI agents use.

   4. <a id="1.4"></a>`documents/hosting.md`: running a server.

   5. <a id="1.5"></a>`documents/lua-functions.md`: every function a drone can call.

   6. <a id="1.6"></a>`documents/economy-playbook.md`: how the economy behaves and how to profit from it.

   7. <a id="1.7"></a>`examples/`: starter scripts and company designs, which must still run.

   8. <a id="1.8"></a>`documents/blog/`: a new post when the change is worth one, per [OR-01](../SOPs/OR-01%20Writing%20and%20publishing%20blog%20posts.md).

   9. <a id="1.9"></a>Teaching materials, per [OR-03](../SOPs/OR-03%20Promoting%20Ex%20Machinis%20to%20schools%20and%20learners.md), when the change alters a lesson's code or steps.

   10. <a id="1.10"></a>`README.md` and `CLAUDE.md`, when the change alters setup, layout or how the project is run.

   11. <a id="1.11"></a>The SOPs in `Procedures/`, when the change alters a procedure, per [QA-01](../SOPs/QA-01%20Writing%20and%20maintaining%20Ex%20Machinis%20standard%20operating%20procedures.md).
