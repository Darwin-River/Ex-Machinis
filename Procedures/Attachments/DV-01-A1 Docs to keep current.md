# DV-01-A1: Docs to keep current

1. <a id="1"></a>When a change affects players, update these docs in the same pull request. This list is the one in `CLAUDE.md`, "Docs to keep current"; keep the two the same.

   1. <a id="1.1"></a>`documents/players-manual.md` (and its page under `resources/views/pages/`)

   2. <a id="1.2"></a>`documents/design-manual.md`

   3. <a id="1.3"></a>`documents/api.md`

   4. <a id="1.4"></a>`documents/hosting.md`

   5. <a id="1.5"></a>`documents/lua-functions.md`

   6. <a id="1.6"></a>`documents/economy-playbook.md`

   7. <a id="1.7"></a>`documents/sustainability-playbook.md` (costs, the support page, social accounts, who owns what)

   8. <a id="1.8"></a>`documents/open-source-pathway.md` (the licence, the shared organization, the site's design)

   9. <a id="1.9"></a>`documents/blog/` when the change is worth a post, per [OR-01](../SOPs/OR-01%20Writing%20and%20publishing%20blog%20posts.md). A new post is announced on Bluesky and Mastodon automatically when it reaches `main`.

2. <a id="2"></a>Also check these, and update the ones the change touches:

   1. <a id="2.1"></a>`examples/`: starter scripts and company designs, which must still run.

   2. <a id="2.2"></a>Teaching materials, per [OR-03](../SOPs/OR-03%20Promoting%20Ex%20Machinis%20to%20schools%20and%20learners.md), when the change alters a lesson's code or steps.

   3. <a id="2.3"></a>`README.md`, `CONTRIBUTING.md` and `CLAUDE.md`, when the change alters setup, layout or how the project is run.

   4. <a id="2.4"></a>`config/support.php`, when the change alters the running costs, per [FR-01](../SOPs/FR-01%20Raising%20funds%20through%20Ko-fi.md).

   5. <a id="2.5"></a>The SOPs in `Procedures/`, when the change alters a procedure, per [QA-01](../SOPs/QA-01%20Writing%20and%20maintaining%20Ex%20Machinis%20standard%20operating%20procedures.md).
