# AD-01-M2: Machine instructions for identifying and posting issues

1. <a id="1"></a>Always review and follow the most recent version of these instructions.

2. <a id="2"></a>Scope

   1. <a id="2.1"></a>Apply these instructions whenever, during other work, you notice a bug, a gap in the docs, a confusing game rule, a slow or unclear procedure, or another chance to improve the game, and it is outside the task in hand.

   2. <a id="2.2"></a>A problem inside the task in hand is fixed as part of it, but a bug still gets its own issue, per [AD-01](../SOPs/AD-01%20Creating%20and%20resolving%20GitHub%20issues.md) §4.2.

3. <a id="3"></a>Posting an issue

   1. <a id="3.1"></a>Search open and closed issues first. If one already covers it, add a comment there instead of a new issue.

   2. <a id="3.2"></a>Write the issue per [AD-01](../SOPs/AD-01%20Creating%20and%20resolving%20GitHub%20issues.md) §5.1, link the files it mentions per §5.5, and attribute it per §5.6.

   3. <a id="3.3"></a>Post it and carry on with the task in hand. Do not work on the new issue unless you are directed to.

4. <a id="4"></a>Provide a concise summary of activities performed and issues encountered when performing these instructions, listing every issue posted.
