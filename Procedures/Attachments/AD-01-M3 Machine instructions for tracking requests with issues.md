# AD-01-M3: Machine instructions for tracking requests with issues

1. <a id="1"></a>Always review and follow the most recent version of these instructions.

2. <a id="2"></a>Scope

   1. <a id="2.1"></a>Apply these instructions to every request that will change the repository, before starting work on it.

   2. <a id="2.2"></a>A request that only asks for information or analysis needs no issue. A request that continues work already tracked by an issue needs no new one.

3. <a id="3"></a>Tracking a request

   1. <a id="3.1"></a>Fetch `main` and read what has changed since you last looked, so you work from the current code, docs and SOPs. If an SOP has changed, follow its new version.

   2. <a id="3.2"></a>Search open and closed issues for one that covers the request.

   3. <a id="3.3"></a>If an open issue covers it, work against that issue per the "Machine instructions for resolving GitHub issues" ([AD-01-M1](AD-01-M1%20Machine%20instructions%20for%20resolving%20GitHub%20issues.md)).

   4. <a id="3.4"></a>If a closed issue covers it, reopen it, say why in a comment, and work against it.

   5. <a id="3.5"></a>If an issue is related but does not cover all of the request, comment there with how the request extends it, then work against it.

   6. <a id="3.6"></a>Otherwise post a new issue per [AD-01](../SOPs/AD-01%20Creating%20and%20resolving%20GitHub%20issues.md) §5.1, quoting the requester's words, and work against it.

4. <a id="4"></a>Provide a concise summary of activities performed and issues encountered when performing these instructions, including the issue the request was tracked against and whether it is new.
