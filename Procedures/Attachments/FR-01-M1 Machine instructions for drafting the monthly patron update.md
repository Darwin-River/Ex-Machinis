# FR-01-M1: Machine instructions for drafting the monthly patron update

1. <a id="1"></a>Always review and follow the most recent version of these instructions.

2. <a id="2"></a>Scope

   1. <a id="2.1"></a>Apply these instructions when directed to draft the monthly patron update, or another post for patrons. You draft; the project lead publishes. You have no access to Patreon or to patrons' details.

3. <a id="3"></a>Drafting the update

   1. <a id="3.1"></a>Gather the month's work: pull requests merged into `public-forge`, playtest rounds on #380, new blog posts and lessons, and the month's "Social posts" issues. Read the last "Patron update" issue so you don't repeat it.

   2. <a id="3.2"></a>Draft the update from the "Monthly patron update template" ([FR-01-T1](FR-01-T1%20Monthly%20patron%20update%20template.md)). Lead with what changed for players and learners, in plain words, with one short Lua snippet or image suggestion if it helps.

   3. <a id="3.3"></a>Follow [FR-01](../SOPs/FR-01%20Raising%20funds%20through%20Patreon.md) §4: no gameplay advantage for patrons, no patron named without consent, and an honest picture of what is done and what is not.

   4. <a id="3.4"></a>In the third month of each quarter, include the "What your support paid for" section, and leave the figures for the project lead to fill in. Do not guess amounts.

   5. <a id="3.5"></a>Check every fact and link against the repository.

   6. <a id="3.6"></a>Post the draft in an issue titled "Patron update: {month year}", labeled `patreon`, attributed per [AD-01](../SOPs/AD-01%20Creating%20and%20resolving%20GitHub%20issues.md) §5.6. Suggest one social post to go with it, per the "Social media post template" ([OR-02-T1](OR-02-T1%20Social%20media%20post%20template.md)).

4. <a id="4"></a>Provide a concise summary of activities performed and issues encountered when performing these instructions, including the issue that holds the draft.
